# __WORKFLOW_NAME__

Batch LLM inference on Nexus, generated by `nexusctl init llm-batch-inference`.

```
plan_shards --> infer_shard x N (one per shard) --> aggregate
```

| Task | What it does | Policy |
|---|---|---|
| `plan_shards` | Counts the prompts and cuts them into `shard_size` slices | at most `MAX_SHARDS` (256) shards |
| `infer_shard` | **map** over the shards: asks the model every prompt of its slice, checkpoints every `checkpoint_every` answers, writes `output_prefix/part-NNNNN.jsonl` | retried on `rate_limited`, `transient`, `worker_lost`, ...; memoized 30 days; output `max_bytes=2048` |
| `aggregate` | Checks every shard and record was answered exactly once; totals tokens and an estimated cost | `trigger_rule=all_done`, fails naming missing shards |

## What the platform does for an LLM task

`infer_shard` calls the model through `nexus.llm.LLMClient`, which on every call:

- **takes a permit** from the platform's shared rate limiter on the keys
  `[<provider>, <provider>/<model>]`, so 200 shards on 40 workers stay under
  one provider limit together. Limits are namespace policy (see below); a key
  with no limit configured is granted at once.
- **retries 429 and 503 in the task**, honouring `Retry-After`. When that is not
  enough it raises `nexus.RateLimited`; the platform retries the task later
  (error class `rate_limited`) without charging its retry budget, up to a cap.
- **reports token usage** under `tokens:<provider>/<model>:input|output|cached`
  and `requests:<provider>/<model>`. The units reach the usage ledger with the
  attempt's end, including for an attempt that failed half way.

## Resuming mid-shard

Every `checkpoint_every` answers, the task calls `ctx.checkpoint(state)` with
its cursor and the answers so far. A retry of the same shard (a lost worker, a
provider outage past the in-task retries, a deadline) starts with
`ctx.resume()` and skips every prompt already answered, so the only prompts
paid for twice are the ones answered after the last checkpoint. Pick
`checkpoint_every` by what a re-asked prompt costs you versus a checkpoint
write. The checkpoint holds the answers themselves; for very large shards or
long answers, write parts to object storage and checkpoint the part list.

The platform fences checkpoints: an attempt that has lost its lease cannot
overwrite a newer attempt's checkpoint. The answers file is written under a
temporary name and renamed, so a crash never leaves a truncated part file.

## Cost

`aggregate` reports `estimated_cost_usd` from `example_prices`, an
**illustrative** price table (USD per million tokens) so the report has a
number in it. It is not the platform's price book and not any provider's
current price: the platform prices the recorded usage units separately.
Override it with `--param 'example_prices={"input_per_1m_tokens_usd": ..., "output_per_1m_tokens_usd": ...}'`.

## The mock, and pointing at a real provider

The defaults (`base_url=http://mock-llm:8089`, `api_key_env=""`) target the
SDK's mock model server, which answers deterministically and costs nothing:

```bash
python -m nexus.testing.mock_llm --host 0.0.0.0 --port 8089   # as a sidecar named mock-llm
```

For a real provider, pass its URL and the **name** of the environment variable
that holds the key, and deliver the key to the task through the platform's
secret mechanism: set `API_KEY_SECRETS` in `dag.py`, e.g.
`[SecretRef(name="OPENAI_API_KEY", ref="vault://kv/llm/openai")]`, which the
worker resolves at execution time into that environment variable. Never put a
key in a parameter, the spec or an input: those are stored and shown.

| Provider | `provider` | `base_url` | `api_key_env` |
|---|---|---|---|
| OpenAI (or OpenAI-compatible) | `openai` | `https://api.openai.com` | `OPENAI_API_KEY` |
| Anthropic | `anthropic` | `https://api.anthropic.com` | `ANTHROPIC_API_KEY` |

With `api_key_env` empty the task sends a placeholder key that only the mock
accepts; a real provider refuses it with 401, which fails the task terminally.

The task needs network egress to reach the model. The agent's docker executor
runs containers with `--network none` by default; run these tasks on workers
whose docker executor is configured with a network, or with the subprocess
executor.

Configure the namespace's rate limits to the provider's real limits before
fanning out:

```json
"rate_limits": {
  "openai":             {"requests_per_second": 50},
  "openai/gpt-4o-mini": {"requests_per_second": 50, "tokens_per_minute": 2000000}
}
```

(`PUT /v1/namespaces/__NAMESPACE__/quotas`, the same document as the quotas.)

## Input

JSON Lines, one record per line: `{"id": "...", "prompt": "..."}`, optionally
`"system"` (a system prompt) and `"expected"` (a reference answer, to have the
aggregate report accuracy). Or `synthetic://N` for N arithmetic prompts.

## Develop

```bash
python -m venv .venv && . .venv/bin/activate
pip install -r requirements.txt pytest
pytest          # starts the mock in-process: no key, no network, no cost
nexusctl workflow compile dag.py --show
```

The tests cover a mid-shard crash and resume (the mock's own request counter
proves no answered prompt is asked twice), 429 handling and token accounting.

## Deploy and run

```bash
docker build -t __WORKFLOW_NAME__:0.1.0 .   # then push, and set IMAGE in dag.py
nexusctl workflow submit dag.py --namespace __NAMESPACE__
nexusctl run create __WORKFLOW_NAME__ --namespace __NAMESPACE__ \
    --param source=/data/prompts.jsonl --param shard_size=500 \
    --param model=gpt-4o-mini --param base_url=https://api.openai.com \
    --param api_key_env=OPENAI_API_KEY --wait
```

`source` and `output_prefix` are paths inside the task container: mount shared
storage there, or change `_records` and the output writer to use object storage.
