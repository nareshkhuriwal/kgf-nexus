# __WORKFLOW_NAME__

A hyperparameter search on Nexus, generated by `nexusctl init ml-training`.

```
load_dataset --+--> train x N (one per trial) --> select_best --> evaluate --> quality_gate
make_grid -----+
```

| Task | What it does | Policy |
|---|---|---|
| `load_dataset` | CSV (target in the last column) or a synthetic problem; seeded train/test split | memoized 1 day |
| `make_grid` | learning rates x L2 values -> trials | at most `MAX_TRIALS` (64) |
| `train` | **map** over the trials: ridge regression, scored on a validation slice | memoized 7 days, `max_fanout=64`, output `max_bytes=4096` |
| `select_best` | best validation R^2 | `trigger_rule=all_done`: failed trials are skipped, not fatal |
| `evaluate` | refit the winner, score the held-out test set | memoized |
| `quality_gate` | **fails the run** if test R^2 < `min_r2`; otherwise emits a model card | no retry |

## Things worth knowing

- **The fan-out is decided at run time.** `train.map(...)` creates one child per
  element of `make_grid`'s output. `max_fanout` is mandatory: a grid bigger than
  it fails the node explicitly instead of flooding the cluster.
- **Re-runs are cheap.** Every trial is a pure function of (hyperparameters,
  dataset) and memoized. Widen the grid and re-run: finished trials are reused
  and only the new ones train.
- **The fan-in is bounded by proof.** `train` declares `max_bytes=4096` on its
  output, so at submit the control plane checks that 64 x 4 KiB fits its fan-in
  limit, and the task refuses to emit a larger result.
- **The test set is untouched until the end.** Trials are scored on a validation
  slice of the training data; only `evaluate` looks at the test split.

The model is plain Python so the template runs anywhere. Replace `_fit` and
`_predict` with scikit-learn, XGBoost or PyTorch (add them to
`requirements.txt`); the DAG stays the same.

## Develop

```bash
python -m venv .venv && . .venv/bin/activate
pip install -e /path/to/kgf-nexus/sdk/python -r requirements.txt pytest
pytest
nexusctl workflow compile dag.py --show
```

## Deploy and run

```bash
docker build --build-context nexus-sdk=/path/to/kgf-nexus/sdk/python \
    -t __WORKFLOW_NAME__:0.1.0 .   # then push, and set IMAGE in dag.py
nexusctl workflow submit dag.py --namespace __NAMESPACE__
nexusctl run create __WORKFLOW_NAME__ --namespace __NAMESPACE__ \
    --param rows=5000 --param 'learning_rates=[0.01,0.1]' --param min_r2=0.9 --wait
```

Use your own data with `--param source=/data/train.csv` (a path the task
container can read; numeric columns, target last, one header row).
