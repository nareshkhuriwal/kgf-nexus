# __WORKFLOW_NAME__

An ETL pipeline on Nexus, generated by `nexusctl init etl`.

```
extract --> validate --> transform --> load
```

| Task | What it does | Policy |
|---|---|---|
| `extract` | Reads the CSV at `source` (path, `file://`, `http(s)://`), checks the required columns, fingerprints the bytes | retried 4x on transient/timeout/infrastructure errors |
| `validate` | Rejects bad rows with a reason each; fails the run if more than `max_reject_ratio` are bad | no retry: it is deterministic |
| `transform` | Integer cents, upper-case currency, per-day totals | pure, so memoized for 7 days |
| `load` | Upserts orders and totals into `target_db` | idempotent: see below |

## How `load` stays correct under retries

Nexus runs tasks **at least once**: a worker can die after the database
committed but before the platform heard about it, and the retry runs `load`
again. `load` makes that harmless with a *conditional write*: in one transaction
it checks `load_batches` for `ctx.idempotency_key`, writes the rows, and records
the key. The key is derived by the platform from (run, node, task version) and
is identical on every retry, so a retry either finds the batch (and returns) or
finds nothing written at all.

Rows are upserted by `order_id` and daily totals are recomputed from the table,
so loading an overlapping file in a *new* run cannot double-count either.

SQLite keeps the template self-contained. For Postgres, replace `_connect`; the
`ON CONFLICT` SQL works unchanged.

## Input format

```csv
order_id,customer_id,order_date,amount,currency
o-1,c-1,2026-09-01,10.50,USD
```

Edit `REQUIRED_COLUMNS` and `_check_row` in `dag.py` for your own schema.

`data/orders.csv` is a 31-row sample with one bad row (an impossible date),
which `validate` rejects without failing the run. It is copied into the task
image at `/app/data/orders.csv`, so a first run needs no external data:

```bash
nexusctl run --local dag.py --param source=data/orders.csv --param target_db=warehouse.db
nexusctl run create __WORKFLOW_NAME__ --param source=/app/data/orders.csv \
    --param target_db=/tmp/warehouse.db --wait   # a path the task user can write
```

## Develop

```bash
python -m venv .venv && . .venv/bin/activate
pip install -e /path/to/kgf-nexus/sdk/python -r requirements.txt pytest
pytest                                    # runs the real task functions
nexusctl workflow compile dag.py --show   # the exact spec the server will see
```

## Deploy and run

```bash
docker build --build-context nexus-sdk=/path/to/kgf-nexus/sdk/python \
    -t __WORKFLOW_NAME__:0.1.0 .   # then push, and set IMAGE in dag.py
nexusctl workflow submit dag.py --namespace __NAMESPACE__
nexusctl run create __WORKFLOW_NAME__ --namespace __NAMESPACE__ \
    --param source=https://example.com/orders.csv --wait
```

`target_db` defaults to `/data/warehouse.db`, a path inside the task container:
mount a volume there, or pass a path your workers share. Run it nightly with:

```bash
nexusctl schedule create __WORKFLOW_NAME__-nightly --workflow __WORKFLOW_NAME__ \
    --cron "30 2 * * *" --timezone UTC --param source=https://example.com/orders.csv
```
