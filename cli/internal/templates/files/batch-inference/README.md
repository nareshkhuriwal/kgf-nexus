# __WORKFLOW_NAME__

Sharded batch inference on Nexus, generated by `nexusctl init batch-inference`.

```
plan_shards --> infer x N (one per shard) --> aggregate
```

| Task | What it does | Policy |
|---|---|---|
| `plan_shards` | Counts the records and cuts them into `shard_size` slices | at most `MAX_SHARDS` (256) shards |
| `infer` | **map** over the shards: scores a slice, writes `output_prefix/part-NNNNN.jsonl` | memoized 30 days (the checkpoint), retried on a different worker, `max_bytes=1024` |
| `aggregate` | Checks every shard reported and totals the results | `trigger_rule=all_done`, fails naming missing shards |

## Checkpointing

Each `infer` child is memoized on (shard, model, output prefix, threshold). Its
small summary is the shard's checkpoint:

- A run that fails at shard 180 of 200 is **retried**, not restarted: the 179
  finished shards come from the cache, and only the failed ones are scored.
- Re-running the same input with the same model is nearly free.
- Changing the model (its JSON, including `version`) changes the cache key, so
  everything is re-scored. That is the behaviour you want.

Prediction files are written to a temporary name and renamed into place, so a
crash never leaves a truncated `part-*.jsonl` behind.

To force re-scoring with an unchanged model (say the input file was corrected
in place), invalidate the cache:

```bash
nexusctl cache invalidate --task-ref __WORKFLOW_NAME__.infer --reason "input corrected"
```

## GPUs

`USE_GPU` in `dag.py` makes each shard request one `GPU_KIND` GPU (generate with
`nexusctl init batch-inference --gpu` to start with it on). A GPU task only
starts on a worker that advertises a matching GPU; the worker exposes the
assigned device as `CUDA_VISIBLE_DEVICES`. The template's scoring is plain
Python, so replace `_score_batch` with your framework's batched forward pass
(and add it to `requirements.txt`) to actually use the device.

## Input

JSON Lines, one record per line: `{"id": "...", "features": [f1, f2, f3, f4]}`.
Or `synthetic://N` to generate N records, useful for sizing the fleet.

## Develop

```bash
python -m venv .venv && . .venv/bin/activate
pip install -r requirements.txt pytest
pytest
nexusctl workflow compile dag.py --show
```

## Deploy and run

```bash
docker build -t __WORKFLOW_NAME__:0.1.0 .   # then push, and set IMAGE in dag.py
nexusctl workflow submit dag.py --namespace __NAMESPACE__
nexusctl run create __WORKFLOW_NAME__ --namespace __NAMESPACE__ \
    --param source=/data/input.jsonl --param shard_size=5000 --wait
```

`source` and `output_prefix` are paths inside the task container: mount shared
storage there, or change `_records` and the output writer to use object storage.
